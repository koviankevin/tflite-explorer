# 探索草稿儲存失敗與重試

本輪依使用者「挑重要的做，先完成一版」的指示，只補齊會影響日常資料保存的缺口，再交付固定版本。跨 OS 實機、數小時 interpreter、完整新手／螢幕閱讀器、斷電及任意格式遷移保留為後續工作；不再作為這一版的新增關卡。公司與手機不在本輪範圍，Firefox／WebKit 為選做。

## 行為

探索草稿寫入失敗時會持續顯示「尚未儲存」，保留目前搜尋、圈選、視角及 Undo／Redo。後續操作繼續在記憶體中記錄，不自動反覆嘗試失敗的資料庫。自動儲存仍開啟時，可按「重試儲存草稿」；停用自動儲存時，重試按鈕停用，不會偷偷保存。

重試只在 transaction 完成後顯示成功。若最初連本機草稿都讀不到，會先重新讀取；找到既有草稿後要求恢復或另開副本，不直接覆蓋。跨分頁 revision 已變更時，原本的衝突保護保持有效。模型切換途中才完成的舊重試不能附到新模型。

本機記錄最多 20 份。達上限時可從「探索草稿」下載 JSON，核對備份後明確移除一份，再重試目前草稿。瀏覽器清除資料、儲存空間回收及斷電仍不保證復原；重要工作請下載備份。本版不更動資料庫格式、保存上限或原記錄。

## 驗證與發布狀態

舊程式的真實保存控制器回歸測試失敗：寫入拋出 `QuotaExceededError` 後 `storageFailed` 仍為 false。原因是寫入 catch 只設衝突旗標，未記錄其他儲存錯誤；讀取失敗的分支已有錯誤狀態。修正後相關 37 項 Node 測試通過，涵蓋 quota／權限失敗、同步失敗、重試／暫停、舊版本保留、Undo／Redo、跨分頁及切換模型。

Hosted Chromium 新流程使用隔離 context，以原生選檔／按鈕真正建立 20 份探索草稿，讓第 21 份觸發既有上限，再下載備份、移除一份、Enter 重試及重載恢復。CDP 僅讀 DOM；不直接改 IndexedDB、不注入 quota、不改安全設定或使用 fake timers。容量上限案例不冒充 OS 磁碟已滿或斷電測試。
