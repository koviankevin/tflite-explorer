# Pattern 清單保存與多分頁

自 `0.2.0-preview.4` 起，pattern 清單使用獨立的 IndexedDB `model-lens.pattern-library.v4`。每次新增、更新或匯入都在同一個 read/write transaction 內讀取最新清單再保存；成功狀態只在 transaction 完成後顯示。BroadcastChannel 僅傳遞清單 revision，通知其他分頁重新讀取；沒有通知時，分頁取得焦點仍會檢查新版。

不同名稱的新增項目會合併。同名項目的內容若已被另一分頁修改，自己的版本會另存為 `名稱（2）` 等副本，既有版本保留。重試相同保存不會再製造相同副本。另一分頁更新清單時，正在編輯的結構、條件與圈選不會被自動套換；要使用新版內容，請從已儲存清單重新選取。保存期間若繼續改動結構，也保留新的編輯，不用剛完成保存的舊快照覆蓋它。

匯入會在提交時，以最新清單重新計算略過與改名，完成訊息顯示實際結果。因此另一分頁剛新增資料時，完成數量可能與先前預覽不同。最多保存 50 組，清單內容最多 1 MiB；超限或儲存失敗會中止整筆操作，不留下半份匯入。容量不足時可下載目前的工作階段，或匯出已儲存的 patterns 備份。

首次使用時，依序讀取舊 localStorage v3／v2／v1 中第一個存在的清單，成功後建立新記錄。舊 keys 的原始內容不修改。舊資料損壞、格式未知或過大時，停止遷移並提示，避免把未知資料當成空清單覆蓋。已建立新記錄後，該記錄為新版網站的保存來源。

舊版分頁繼續使用自己的 localStorage 清單，與新版記錄分開。舊版變更不會自動寫入新版；同時開著時新版會提示，請從舊分頁匯出 JSON，再於新版匯入合併。公開站與內網的不同 origin 也不會自動同步，可用 JSON 帶到另一環境。Pattern JSON 仍沿用既有 version 1／2／3，保留 custom op 類型、條件、SSA ports 和跨 block 控制連線。

清單保存不包含模型或權重，沒有網路同步；工作階段 Undo／Redo 只還原編輯狀態，不回退已提交的整份 pattern 清單。瀏覽器清除網站資料、私密模式或儲存回收仍可能移除本機資料；重要 patterns 請另外下載 JSON。這些機制不代表已完成硬崩潰或公司內網的驗收。
