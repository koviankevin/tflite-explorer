# 超過 20,000 OP 的局部路徑壓測（2026-10-24）

測試模型是單一 function，包含分支、匯合、跨 block 迴圈與 custom OP。原始 21,013 OP，局部匯出後 21,016 OP／7.30 MiB，保留八個圈選 OP，顯示於五個 blocks。五條路徑同時開啟，其中三條長路徑分別有 6,501／7,001／7,540 個輔助節點，分成 87／94／101 段；每段最多 76 個實際輔助節點，另有明示的收合標記。

## 發現並修正

1. 結構對照在單一大型 cyclic function 超過原本 2 MiB 上限而拒絕匯出。改為 8 MiB 有限額度；來源檔案仍有獨立的 64 MiB 限制，schema、SSA／dominance 與 SHA-256 結構驗證沿用。新增 >20,000 OP 的真實匯出／重開回歸案例，確認超過舊額度的對照仍被正確辨識並沿用 pattern。
2. 清除選取時只清 Set、未重設其 graph 身分；重繪又將舊 buffer 寫回 Map，可能造成不同 blocks 共用 Set。瀏覽器重現八個可見 OP 卻算九個選取、清除一個 block 同時清掉另一個、匯出回報無效 layer。清除／關閉模型改成新建 Set 並同步 graph；跨 block 重繪只讀取各 graph 自有的集合，不再將舊 buffer 回存到過期 graph。

瀏覽器回歸先切換 block、展開、清除，再重新選取與加入全部原始 OP，確認恰為八個；清除左分支只移除該 block 兩個 OP，另一個 block 的選取保持不變。接著重新做完整壓測並實際匯出。

## 效能與記憶體

環境：Node.js v24.19.0、Intel i5-10400；瀏覽器使用 32px 圖字、約 81% 縮放。

- 核心引擎暖機後 30 輪、180 次切段／收起／重開，包含 DTO structuredClone；每輪結束執行 GC。前五輪存活 heap 平均 266.84 MiB，後五輪 266.94 MiB，相差 0.10 MiB。快取保持一個 region 索引、五個路徑計畫。
- 引擎單次 DTO 中位數 38.94 ms、p95 69.57 ms；整輪含 GC 前五輪平均 334.81 ms、後五輪 317.81 ms。首次路徑分析分七次接續，遵守每次 50,000 工作單位上限。
- 修正後瀏覽器連續 20 輪、100 次操作，每輪三條長路徑各下一段、收起右匯合路徑、再重新開啟。前 25 次繪圖中位數 434 ms，後 25 次 451 ms，觀測範圍 358–610 ms。
- 瀏覽器主執行緒 `performance.memory.usedJSHeapSize` 採樣約 13.55–50.44 MiB，最後一輪 25.12 MiB，會隨自然 GC 回落；同一輪末狀態的 DOM 為 3,402–3,405，沒有逐輪增加。此 API 不是模型 worker 或整個瀏覽器程序的記憶體；worker 相關演算法的存活資料以獨立 Node GC 壓測佐證，未宣稱取得完整瀏覽器程序記憶體。
- 全部 100 次操作保留三個已選 OP，縮放相對 81% 最大差約 0.0000025；操作後可繼續加入到八個原始 OP，輔助節點不參與選取。

這是有限輪數的合成模型量測，沒有觀察到持續退化或存活記憶體累積，不代表任意模型、任意操作時間皆無資源上限。

## 匯出與驗證

壓測後實際下載的局部 MLIR 重新解析仍為 21,016 OP、精簡圖八個原始 OP；舊 pattern 一次匹配，custom OP 屬性及 i64 數值保留。以原生 `iree-opt --allow-unregistered-dialect --mlir-print-op-generic` 檢查語法、SSA／dominance／CFG，退出碼 0，原生印出後仍匹配一次。此驗證不包含未註冊 custom dialect 的執行語意。

相關自動化共 59 通過、1 個環境式原生 compiler 案例略過；本次另以已安裝原生工具驗證實際大型下載檔。暫時 heap／DOM 診斷 UI 僅用於本機壓測，發布前移除並重新建置；正式站另核對產物與實際選檔、匯出重開。
